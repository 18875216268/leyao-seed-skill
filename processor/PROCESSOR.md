# 任务处理层（processor）

任务执行的编排者：接收任务后按五步流程推进，全程实时控制纠偏；执行时先按路由地图的节点描述匹配场景——命中资产就原样调用，未命中则按本层自带判据亲自动手（**无任何资产也能完成任务**）。

## 调用链（任务处理层与资产管理层的关系）

```text
任务 → 时机检查：按 version/VERSION.md〈两个时机〉——就绪（每天首次）与更新检测（会话首次）（异步、失败降级）
    → 读 library/ROUTES.md（总路由地图）→ 按节点描述匹配场景，定位可用资产（无资产也照常推进）
    → 五步流程推进（flow/1~5，判据自带）→ 全程 control.md 纠偏
    → 执行步：命中资产则进其挂载目录读 `app.md` 并按其指引**继续向下**（`references/` 等）直到读全 / 足够，再原样调用；无命中按 flow 自带判据自做
    → 交付后：`grow.py trace` 追加轨迹（`--routed` 写命中节点 id / 无命中写 none）；缺能力用 `grow.py propose` 提案
```

## 判据分级（本层准则的硬度约定）

本层每份 flow 的准则分三级，**硬度不同、不可混用**——混用会让判据失效：硬判据被当成建议，验收就没有门槛；软引导被当成判据，就会凭空多出错杀。

| 级别 | 位置 | 是否硬依赖 | 违反后果 |
| --- | --- | --- | --- |
| 出口判据 | 各 flow「出口判据」 | **硬**：逐条核对，不过不得进入下一步 | 阻断，回到本步 |
| 专项判据 | ③ 执行「路由判据」 | **硬**：按序比对，不得跳步 | 选错资产即返工 |
| 动作 | 各 flow「动作」 | **硬**：必须执行；确需例外须在执行留证中写明理由 | 视为本步未做完 |
| 引导 | 各 flow「引导」 | **软**：启发式建议，可裁量；采纳与否不影响验收 | 无（但**不得当判据引用**——引用会把它变成隐形门槛） |

判断口径：**能被第三方按文档核对真假 → 硬（判据）；只能靠经验权衡 → 软（引导）**。
凡"硬"的写"必须／不得／否则回退"；凡"软"的写"可／建议／常见做法"——**禁止把软引导写成必答清单，也禁止把硬判据写成"尽量"**（前者把建议变门槛、后者把门槛变建议，都会让验收失真）。

> **位置约定**：每份 flow 的「出口判据」一律排在「动作」之前——**先知道这一步要过什么门，再去做**（关键判据前置，避免被长文淹没）。
> **按需文件**：形状模板（询问清单 / 口径标注 / 报告骨架）在 `processor/shapes.md`——需要时读，不常驻（常驻只放判据）。

**规则写形式，示例只作样本（写法纪律）**：判据须按**形式 / 范畴**表述；文内列举的案例一律视为**示例（非穷举）**——执行者**不得以「未列举」为由规避** ✗；新增案例只作补充，不改判据形式。

## 资产使用准则（①② 引导 · 软 ｜ ③④ 硬）

任务过程中的四条准则——**①② 属引导（可裁量，采纳与否不影响验收；不得当判据/门槛引用）**；
**③④ 属硬约束（③ 违反即红，由 `run_checks` 的 `paths_external` 拦截；④ 由运行时判据、留证与复核拦截）**：

1. **资产优先，但不强求**：执行时**有匹配就用、是否必要按 ③ 判据 2.6 判**（有匹配就按执行步判据 2 原样调用；**取用顺序**见 ③ 判据 3.5 阶梯：方法论 → 现成资产 → 按需获取 → 先调研 → 亲做）；
   确实不需要时**无需**强行套用——本框架零业务，没有可用资产时按自带判据完成即可。
2. **资产可再获取**：需要资产时，除了直接调用资产层**已挂载**的资产，还可**循资产层的指引获取更多资产**——
   资产文档（`app.md` 及其 references）给出的下载 / 安装 / 接入 / 生成指引，按它取得后即按准则 1 使用；
   新资产要**进资产层**（登记路由与落位）走资产层维护流程（管理台或 `library/engine.py`，见 `library/ROUTES.md`），
   不在任务过程中私改资产层（红线：资产内容一律原样只读）。
3. **运行资产的运行态归用户区**：调用资产会产生运行数据（缓存 / 记忆 / 反馈等）——**必须落用户区**，不得留在框架包内。
   - **归口**：优先用资产自带的 `*_HOME` 类环境变量（如知识库的 `LEYAO_KB_HOME`），指向**框架用户区**（默认与 `.leyao-data/` 同级，建议 `<用户区>/data/assets/<资产id>/`）；无此类变量时，注意其"同级目录"解析结果**是否落进包内**（典型：资产被挂载在 `library/assets/<id>/`，"同级"= `library/assets/` ✗）。
   - **发现包内已有运行态 → 迁移，不要直接删**（多为有用数据：缓存 / 记忆 / 反馈）：迁到用户区对应目录，留痕说明来源与去向。
   - 兜底：`run_checks` 的 `paths_external` 会拦下 `library/` 下的任何点目录/文件（运行态），并提示迁移。
4. **登录 / 凭证（硬 · 通用流程）**：触发＝**命中资产且其路由/文档声明需要登录**；**或：任何步骤依赖的资产（数据 / 工具 / 通道）其路由/文档声明需要登录 → 视为已触发（动手前先入链）**（未声明＝不需要；执行中才发现 → 回触发）：
   - ① **取资产路径（硬）**：**只认两个等价来源**——`python library/asset.py resolve <节点id>`（权威：附实存校验 + 入口文档；**在包根执行**——异 cwd 脚本路径写全即可，**参数与 cwd 无关** ✓）｜ `ROUTES.md` 节点行的 `→ 挂载`（等价）；参数＝**路由节点的 `id`（含任意层级的子节点 / 级联节点 ✓）**；**禁止**以搜索 / 猜测 / 手拼路径等**任何其它形式**获取 ✗（失败 → 〈问题未解决流程〉）；
   - ② **判「凭证已在位？」**（＝**本地缓存 ｜ 用户提供**；「在位」＝**存在性**——文件 / 提供物存在即可；**有效性一律由 ③ 判定** ✗）：**否 →〈登录流程〉**（读该资产〈登录〉说明 →〔**有独立登录器（可满足本需求）？**〕**有 → 必须调用它**（让用户完成登录 → **等待成功**（自动落库 ✓）→ **经其工具取用** ✓：登录器 CLI / 出口命令 / API）——**此时禁止自写登录流程 / 以任何其它形式获取凭证** ✗（自写登录 / 自取二维码 / 自拼鉴权 / 手工拼凑 / 自行读取解析凭证 ✗）；**无 → 自行根据对应资产或其子资产的登录指引获取**——**完整梳理一遍登录流程、自写实现、自行登录** ✓（✗ 不得自创其它路数、不得少梳理一步；流程含用户配合环节〔如扫码〕→ 让用户配合完成 ✓；**指引均未给任何登录流程 → 按能力获取阶梯⑤ 亲做（经用户同意 ✓）+ 交付后提案沉淀 ✓**））→ **获取凭证**；**是 → 直接进入下一环**；
   - ③ **〈验证流程〉**：按该资产〈登录〉说明**验证凭证有效性** → 有效 → **作用<业务域>**；**无效 / 缺失 → 直入闭环**：**重走〈登录流程〉**（见 ②；**有登录器：弹窗＝协助 → 自动落库；无登录器：按指引自行获取**）→ **回本流程**——**同一问题累计 ≤3**，用尽 → 〈问题未解决流程〉 ✓；
   - **任何环节发现「凭证不可用」→ 回 ③ 入闭环（显式 · 硬）**：辅助工具报错 / 取数中途失效 / 任何「凭证不可用」信号 → **回 ③ 重登 → 回验** ✓；**主取数壳**在缺失 / 失效时**自动调起对应独立登录器**＝闭环的实现之一（同一本体；环境异常先按 `--check` 修复后重试）——**agent 无需介入** ✓；**登录器唯一路径（硬）**：登录＝**调起原生扫码窗**（`--reuse` 类；依赖缺失由登录器自动修复环境）；**本登录器不提供无界面 / 出码模式**；**禁止**因"自己是 agent / 走命令执行"改用无界面或出码 ✗、不得据此改走「自行获取」✗；**登录器不可用（判定：修复环境后仍无法弹窗 / 无登录器可用）→ 换其它的合法登录方式（备用通道 / 子资产方式）→ 仍失败 → 询问用户**（用户提供 / 指定后按其走 ✓）；**用户已指定 / 提供凭证或登录方式 → 按其走，不受本链限制** ✓；**未验证不得断言「缺凭证」或向用户索要** ✗、**禁 AI 自行获取凭证** ✗；
   - ④ **〈问题未解决流程〉（统一变量）**：**通用循环以 `processor/control.md`〈卡壳处置〉内〈问题未解决流程〉为唯一源**（≤3 次自动重走 → 是否有优先流程？→ 走〈优先流程〉/重走〈对应流程〉 → 解决？→ 询问用户 → 出口 ✓）；**凭证场景**：自动重登已内联于 ③（≤3 · **同一计数**）——用尽即入其**询问用户**环节 ✓；出口＝〈卡壳处置〉如实收尾；
   - **〈登录总决策链〉（唯一源 · 硬）**：**① 用户明确指定** → 按其执行 ✓（**可指定任一「有说明」的登录方式 / 凭证来源——含资产与各级联子资产**；本轮明确需求优先，见 `control.md` 双准绳裁决）；**② 用户不明确 → agent 自主根据任务需要理解、规划**，按序取用：**1) 总登录框架最高原则**（本 ④ 硬项：唯一入口 / 必须调登录器 / 等落库 / 经工具取用 / 禁自写 / 未验证不索要 / 不静默降级——**包裹层（红线），不是候选方式**）；**2) 资产层自身已说明的登录方式**（其〈登录〉说明标「默认 ✓」者＝**链优先**；未标注 → agent 判断、留证 ✓；同级其余方式 → agent 按需规划优先级 ✓）；**3) 子资产（子优化板块）自身已说明的登录方式**——**排除与上一父级同款** ✗（**同登录器本体 / 同凭证域＝同款**；避免重复）；**4) 若有更多级联资产（更深层级子资产），依次类推**；**出口**：各级不可得 → 〈问题未解决流程〉（≤3 → 询问用户——**此时用户指定＝回 ①** ✓）；**全链红线不越** ✗（禁自写登录流程 / 禁其它形式获取凭证——见本节点〈红线〉）。
   - **实现细节（登录器 / 验证动作 / 业务域规则）一律以该资产〈登录〉说明为唯一源** ✗（**登录器**：该说明须**显式声明位置与调用方式**——相对包根路径 + 在资产根执行 / 异 cwd 全路径 ✓；**本节点无〈登录〉节时，以其路由 / 文档声明的上游凭证入口为准** ✓；本准则不复述系统差异）；
   - **红线**：**禁自写登录流程 / 禁止以其它任何形式获取凭证——范围＝有独立登录器（可满足本需求）时** ✗（不得读其说明 / 代码后另写登录、自取二维码、自拼鉴权）；**无独立登录器 → 自行根据对应资产或其子资产的登录指引获取** ✓（完整梳理、自写自理；不得自创路数 ✗；见 ②）｜**未验证不得断言「缺凭证」或向用户索要** ✗（**索要须附验证留证**）｜**不得因凭证停用资产 / 静默降级 / 绕过所需内容继续 / 带缺口交付 / 交付时才索要** ✗｜**凭证逐资产独立**（不得互推 / 互传 ✗）。
   - **硬度与判断**：**硬（第三方可核对）**＝① 取路径（唯二来源，禁搜索 / 猜测 / 手拼 ✗）· ②「声明需要登录且有独立登录器 → **必须调用该独立登录器**」· ③ **「向用户索要凭证」前必须已完成该资产验证动作并留证（`--status` 输出）——未留证即索要＝红线** · 红线（见上 ✓）；**模型判断（须留证 ✓）**＝判「凭证已在位？」的实际取证、读取并执行资产〈登录〉说明中的验证动作、失败循环内「梳理 / 反思 / 寻找 / 规划」的具体内容；

## 实时控制

执行全程的偏差分级与纠偏见 [control.md](control.md)：low 记录继续 / medium 暂停确认 / high 阻断；安全红线（不静默、先证明后删除、歧义不代选、不可逆前置确认）任何级别不可越过。
同一文件还管**推进控制**（硬判据）：**循环上限**（§1）· **停滞检测**（§2）· **回退与重走**（§3）· **卡壳处置**（§4）· **决策卡点**（§5）——判据与动作一律以 `processor/control.md` 为准（本节只列名，不复述）。

## 与其他层的边界

- 本层只做**编排与执行**，不维护路由与资产内容（那是资产管理层（`library/`）的职责，增删改走 `engine.py`）。
- 经验沉淀不做静默自改——走自我进化层两档：用户区记忆（`.leyao-data/data/memory.md`）自动档与提案守门（内容类仅维护者实例，见 `evolution/EVOLUTION.md`）。
- 版本与更新：属**版本维护层**（`version/VERSION.md`）——就绪与更新检测（时机见该文件〈两个时机〉）；其落地经自我进化层唯一落地器（提案 + apply）。
