# 场景：商品图（输入 → 模式 → 生成 → 输出）

- ID：`goods-image`
- 触发语：「美化这张图」「做张促销图」「按图1 换成图2」「查 X 美化」「换主图」
- 职责：只处理图；价格、库存、状态、上下架不碰

## 0. 原始输入

> 取图要 SCM 登录、生成要生图 key：**先过 §2 拿凭证**。

| 类型 | 来源                                                |
| ---- | --------------------------------------------------- |
| 文字 | 用户提供 / 联网获取 / 自行生成                      |
| 单图 | 用户提供，或从 SCM 查商品取 `logo`                |
| 双图 | 两张可各来自用户或 SCM（如用户参考图 + SCM 商品图） |

**从 SCM 取图（统一用综合搜索）**

```bash
python scm.py query --status 全部 --keyword "<活动ID / 商品编码 / 商品名称 / 批准文号 / 商品ID / 厂家>" --limit 10
```

- `--status 全部` 必加（默认只查进行中）；
- **0 条** → 去空格、用简写或编码主体重试；仍 0 → 请用户给图；
- **1 条** → 直接用；
- **多条** → 取前 10 条，按「商品名称 + 规格」列选项（附状态）让用户选；用户也可自定义（直接给活动ID/编码）。选项按返回顺序，不重排；
- **选中后记下活动ID（`wholesaleId`）**（写回要用，§6.2）；主图取该记录的 `logo`；
- **`logo` 是活动级的**（实测同商品不同活动主图可能不同），不能跨活动套用；
- `logo` 可能是带 `sign` 的链接 → **下载保存文件**；为空 → 请用户提供。

## 1. 模式选择

**判定顺序**：有没有图 → 几张 → 要「换主体」还是「借风格」。

| 条件                               | 模式                       | 说明                                           |
| ---------------------------------- | -------------------------- | ---------------------------------------------- |
| 只有文字                           | **文生图**           | 无实拍商品时用；**不得伪造真实商品包装** |
| 文字 + 单图                        | **原图美化 · 常规** | 去背景杂物、重构背景、摆正主体，干净可直接展示 |
| 文字 + 单图                        | **原图美化 · 设计** | 按商品设计背景 + 文案 + 边框，用于宣传         |
| 文字 + 双图，说「换成/替换主体」   | **参考美化 · 功能** | 保留参考图边框/横幅/徽章/背景，只换中央商品    |
| 文字 + 双图，说「参考风格/借样子」 | **参考美化 · 设计** | 只借色调、光线、氛围，不复制边框与文字         |

- 「把主体换成 X」= 功能模式；「美化 X，参考这张」= 设计模式；
- **默认口径**：只说「美化/美化主图/回传」且没提促销、边框、文案 → **原图美化 · 常规**；提到「促销/宣传/边框/文案」→ **设计模式**；「回传」不改变美化模式；
- **直出 vs 写回**：只说「美化 / 美化主图」= 只出图；说「替换 / 回传 / 换主图」= 写回；
- 拿不准 → 先问一句，不要硬做。

## 2. 凭证获取

按顺序：

```bash
python scm.py status                            # 1
python assets/tpcl/tpcl.py doc                  # 2 参数以线上文档为准
python assets/tpcl/tpcl.py status               # 3 是否有 key
python assets/tpcl/tpcl.py prices               # 4 可用模型与档位
```

| 失败            | 处理                                                                                |
| --------------- | ----------------------------------------------------------------------------------- |
| SCM 退出码 3    | Agent 调起 `login [--account X]`，用户窗内验证码，复验后继续                      |
| `IMAGE_KEY_*` | 给 `purchaseUrl`，购买后 `set-key`；**没有 key 就停在取图前，不要猜模型** |

## 3. 前置校验（缺一不可）

1. 需求是否完全理解（主体、用途、是否要文案/替换）；
2. 输入是否完整（图片够不够、文字齐不齐）；
3. 模式是否选对（对照 §1）；
4. 凭证是否齐全（SCM + 生图）；
5. 写回前：是否已授权（命中触发语即场景授权；否则先说明并征得同意）、是否已存回滚值。

> **任何一条不过 → 回到对应阶段重走**：输入不全回 §0；模式不对回 §1；凭证缺失回 §2；需求没理解 → 先问用户。

## 4. 提示词

### 4.1 构建

- **基本参数**：主图 1:1；促销图默认 1:1（用户另有要求除外）。
- **需求描述**：结构化、短、不重复；一句话说清「主体 + 背景 + 版式」，**不堆禁止项**。

**模式模板（一次提交，直接套）**

```text
文生图：       生成一张{品类}展示图：{主体描述}，{背景描述}，{风格}，1:1。
原图美化·常规：保持包装文字与版式不变，摆正居中，去掉背景杂物，背景换成{背景描述}，1:1。
原图美化·设计：保持包装文字与版式不变，摆正居中，盒体宽约占画面 90%；设计促销版式：边框{颜色/样式}，顶部「{文案}」，底部「{文案}」，角标「{文案}」；背景：{背景描述}。
参考美化·设计：第一张是商品，第二张是风格参考；借鉴第二张图的色调和光线，不要复制它的边框、文字和商品。
参考美化·功能：用第一张图的商品盒子，替换第二张图中央的商品盒子。保留第二张图的边框、横幅、徽章、文字和背景，其他都不要改。
```

- 换背景只加一句「背景换成：…」；要保真只加一句「第一张图包装上的文字保持不变」；
- 参考图里商品占画面主体时：**先试短句**；仍串味（= 参考商品的色块/徽章/文字出现在成品）→ 用背景色遮住参考图商品区域再换，或改设计模式重建。

**背景**：按用户需求或主体调性描述，**不设固定风格**；用户未指定 → Agent 按主体调性写一句（`场景元素 + 色调 + 景深 + 光线`）；实在没把握再问。

**占位符取值**：

| 占位符 | 来源 |
|---|---|
| `{品类}` `{主体描述}` `{风格}` | 用户描述；没说就照图归纳（如「药品包装盒 / 白绿配色 / 商业棚拍」） |
| `{背景描述}` | 用户指定 > 按主体调性自拟（见上） |
| `{颜色/样式}` | 用户指定 > 按包装主色选，不预设 |
| `{文案}` | 下方文案库或自拟；承诺类先确认 |

**营销文案**（B 端：药店/诊所/连锁/批发，不是消费者）

| 类别 | 文案                                           |
| ---- | ---------------------------------------------- |
| 供货 | 库存充足 · 长期供应 · 稳定供货 · 大批量可谈 |
| 发货 | 24 小时发货 · 当日发货 · 现货速发            |
| 渠道 | 厂家直供 · 一级代理 · 区域授权               |
| 资质 | GSP 认证 · 资质齐全 · 随货同行单             |
| 追溯 | 有追溯码 · 批号可查 · 效期新鲜               |
| 售后 | 售后无忧 · 破损包赔 · 质量问题包退换         |
| 场景 | 门店直供 · 诊所专供 · 连锁专供               |
| 结算 | 可开专票 · 支持对账 · 票据齐全               |
| 促销 | 限时特惠 · 新上架 · 热销品种 · 扫码出库     |

自拟：`卖点 + 承诺`，4–8 字（硬上限 12）；角标 ≤4 字并注明「单行不换行」。模板三处文案可只填 1–2 处，未填的不写。
承诺类文案（发货/资质/售后）用户没提时先确认；纯氛围类（限时特惠/热销）可直接用。
不用 C 端话术：药师咨询、七天无理由、假一赔十、家庭常备、爆款推荐、旗舰店、扫码验真。

### 4.2 审查（提交前必过）

| # | 检查项       | 判据                                                                      |
| - | ------------ | ------------------------------------------------------------------------- |
| 1 | 结构完整     | 主体、背景、版式/参数齐全；缺哪项补哪项                                   |
| 2 | 理解正确     | 对「用户要什么」有 **≥95% 把握**；不足 → 回 §3 第 1 条，先问用户 |
| 3 | 无歧义       | 不出现「好看」「高级」「适当」等无法执行的说法                            |
| 4 | 无冗余       | 同一要求不重复；**禁止项不堆叠**                                    |
| 5 | 简单清晰     | 一句话能读懂；模板不超过 4 行                                             |
| 6 | Agent 易理解 | 换另一个 Agent 也能照做，不需要猜                                         |

> 任何一条不过 → 回 §4.1 改提示词，重审通过后再提交。

## 5. 出图

### 5.1 提交

```bash
python assets/tpcl/tpcl.py generate --prompt "<§4.1 模板>" `
  --image <主体图> [--image <参考图>] `   # 文生图省略 --image
  --out out/<活动ID>/ --model <prices 里的模型，优先 2.5-flash> --size 1:1 --image-size 1K
# 构图确认后 --image-size 2K 出终稿
```

- 双图顺序：**主体在前、参考在后**（反了只换背景）；
- 角色由 Agent 看图裁决，判不准按用户发图顺序给选项；
- `--out` 建议必填（不传只返回 1 小时有效的 URL，无法归档）。

### 5.2 审查（只查构图）

| 项 | 判据 |
|---|---|
| 比例 | 1:1 |
| 主体宽 | 主图 85% / 促销图 90%（±0.01；用户另指定时以指定值为准） |
| 居中 | dx = dy = 0（±5px） |
| 边界 | 四周无异常缝隙、断边、空白条带；留白均匀 |

不达标 → 按 §7「留白兜底」校正（**不重新生成**），校正后复测。

> 其余（背景、光影、倒影、角度、氛围）由模型自行设计，**不作为缺陷、不检查、不干预**。

## 6. 输出结果

### 6.1 直出

本地文件（`saved`）+ 在线直链（1 小时有效）；`saved` 为空用 `tpcl.py job <id> --out <目录>` 补下载。

### 6.2 写回 SCM（回传 / 替换主图）

> 本节是**命令行等价实现**；写 Python 脚本时优先调 `core/http.py::upload_file`（见 `references/商品/api_商品写入.md §1.4.1`），不得改写 Cookie/multipart 逻辑。

```powershell
$cred = Get-Content "$env:LOCALAPPDATA\scm-operations-query\credential.json" -Raw -Encoding UTF8 | ConvertFrom-Json
$token = $cred.token; $pidm = $cred.provider_id_m
$cookie = ($cred.cookies.PSObject.Properties | ForEach-Object { "$($_.Name)=$($_.Value)" }) -join "; "
$t = Get-Date -Format 'yyyy-MM-dd HH:mm'

# 0) 先存旧图（回滚值；签名链接必须落盘）
Invoke-WebRequest -Uri "<旧 logo>" -OutFile "out/<活动ID>/old.jpg"

# 1) 上传新图（字段名必须是 file）
curl.exe -s -X POST "https://scm.ysbang.cn/scm-base/common/upload2Local" `
  -H "provideridm: $pidm" -H "Cookie: $cookie" `
  -F "file=@C:\path\new.png" `
  -F "token=$token" -F "platform=scm-admin" -F "version=1.0.3" `
  -F "ua=Mozilla/5.0" -F "ex=goodsOnShelves" -F "lastBuildTime=$t"
# → {"code":"40001","data":"https://img.ysbang.cn/..."}
# 成功判据：code=40001 且 data 是 URL（不是 code=0）；lastBuildTime 取当前时间 YYYY-MM-DD HH:MM

# 2) 替换主图
$body = @{ wholesaleId = <活动ID>; logo = "<上一步 data>"; token = $token;
           platform = "scm-admin"; version = "1.0.3"; ua = "Mozilla/5.0";
           ex = "goodsOnShelves"; lastBuildTime = $t } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "https://scm.ysbang.cn/scm-goods/wholesaleDrugOnsale/updateLogo" `
  -Headers @{ provideridm = $pidm; Cookie = $cookie } -ContentType "application/json" -Body $body
```

- **必须带 Cookie（含 cmsToken）**，只传 token 会 `40020`；
- PowerShell 5.1 读凭证必须 `-Raw -Encoding UTF8`：否则中文乱码 → `ConvertFrom-Json` 失败 → Cookie 为空 → 同样 `40020`（已实测）；
- `updateLogo` 成功判据：`code=40001`；
- 复验：`query --status 全部 --keyword <活动ID> --limit 1` → `rows[0].logo` 必须等于新直链（比对 `logo`，不是 `logoUrl`/`drugLogo`）；
  - `全部` 不含「已结束」：活动已结束时改 `--status 已结束`，或直接 `--keyword <活动ID>`；
  - 0 行时先 `--status 已结束` 再试一次，仍 0 则说明活动不存在；
- 回滚 = 重传 `old.jpg` + `updateLogo`；
- 审计：向 `%LOCALAPPDATA%\scm-operations-query\write-audit.jsonl` 追加一行 JSON（`time/interface/target/params 脱敏/before/after/result/stage`）。

## 7. 限制与错误

**红线**

| 项 | 说明 |
|---|---|
| 未授权 | 不写回；授权后只改主图，不顺带改价/库存/状态 |
| 文案禁区 | 具体价格折扣、绝对化用语、医疗功效、无法兑现的承诺 |

**构图算法**

| 项 | 说明 |
|---|---|
| 主图比例 | 必须 1:1；**主体宽：主图 85%、促销图 90%**（用户可另指定）；主体中心与画布中心重合（偏移为 0） |
| 留白兜底 | side = 主体宽 ÷ 0.85，以主体 bbox 中心裁方 → 缩至 2048；偏大 → side 取 max(宽,高)/0.85，仍超出则补背景；偏移 → 以 bbox 中心重裁 |
| 档位点数 | 1K=1 / 2K=2 / 3K=3 / 4K=4（以 `prices` 为准） |

**操作与备注**

| 项 | 说明 |
|---|---|
| 标识 | 统一 `--keyword` 综合搜索；选中记录后取其 `wholesaleId` 写回 |
| 主图归属 | **活动级**（§0）：必须用选中活动的 `logo` |
| 详情图 | `picsAudit`（提交）→ `picUrlList`（生效），走 `addWholesale` 的 `mode=edit` 全量表单；**无独立接口**，见 `references/商品/zddz.md` §2.5 |
| 接口归类 | `upload2Local` 在接口总表归「首页/常用工具」，属通用上传 |

**错误**

| 现象 | 处理 |
|---|---|
| `AUTH_*` / 40020 | 带 Cookie 重试；仍失败 → 调起 login |
| `MODEL_NOT_FOUND` | `prices` 重取模型，不要自换 |
| `UNSUPPORTED` | 换已开放档位 |
| 429 / `1015` | 等 30–60 秒重试一次 |
| 复验未变 | 等 2–3 秒重查，仍不变则回滚 |

