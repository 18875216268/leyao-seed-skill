# 资产层（assets）

> 定位：放置**可复用的工具**或**高频业务场景配方**。一个资产一个文件夹，互不依赖。

## 0. 使用时机（Agent 必读）

1. **任务开始前**：先 `python scm.py assets`；若 `ljgl` 有对应高频场景，按其 GUIDE 执行；无匹配再自行规划；
2. **任务卡点**：需要外部方法/工具时，先查本目录是否有现成资产可用，或从对应 GUIDE 获取思路；没有再自行规划；
3. **仍不足时**：可联网检索文章/论文/类似案例，再回到本目录或自行实现。

## 2. 新增资产规则

1. 新建 `assets/<资产名>/` 文件夹；
2. 必须包含 `GUIDE.md`，写清：**用途 / 输入 / 输出 / 命令示例 / 限制**；
3. 在本文件 §1 表格登记一行；
4. 资产**只能依赖自身目录内文件与技能核心层**，不得反向修改 `core/`、`modules/`；
5. 资产之间不得互相引用。
6. **高频场景（`assets/<场景>/`）若需封装为可执行入口，必须三件套**：
   - `GUIDE.md`：流程手册（为什么/红线/回滚），仍是唯一「为什么」来源；
   - `scene.json`：元数据 `{name, version, summary, actions, write, entry, requires}`——**列表只读它，不 import 代码**；
   - `entry.py`：实现；模块级 `SCENE` 必须等于 `scene.json.name`；`main(argv) -> int` 返回与主 CLI 相同退出码（0/1/2/3）；**顶层不得有网络/IO 副作用**。
7. 统一入口：`python scm.py scene <场景> <动作> [...]`；参数由场景用 argparse 自解析，`--account` 可透传。
8. **加/删场景不改 `scm.py`**：增删目录即生效；`scene.json` 加 `"disabled": true` 可临时下线。
9. 场景目录可放私有数据文件（如键骨架 JSON），但**不得被其他场景引用**。
10. 封装只做「多步固定编排 + 写操作护栏」；**纯查询不要封装**（用 `query`/`call` 直连）。

## 3. 与技能核心的边界

| 层 | 关系 |
|---|---|
| `core/`、`modules/` | 技能主能力；资产只调用，不修改 |
| `assets/` | 可选能力；不加载也能正常使用技能 |
| `references/` | 知识文档；资产需要时自行引用路径 |
