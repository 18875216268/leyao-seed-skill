# 优惠券系统 · 前端过滤规则（AI 自带能力）

> 目的：把前端隐性过滤固化为**规则表 + 可执行工具**，Agent 直接查表/调用，不临场发挥。
> 工具：同目录 `coupon_filters.py`（规则 1:1 转写源码，含 12 个过滤函数 + 3 个命名函数 `make_coupon_name`/`extract_suffix`/`make_activity_name`）。Agent 直接 `from coupon_filters import *` 调用，不临场写判定。
> 标注：🧠=需语义判断（Agent 按规则表人工处理）｜🔧=已固化为工具函数（直接调用）｜🌐=服务端处理（前端无规则）

---

## 1. 搜索与列表
| 过滤 | 类型 | 规则 |
|---|---|---|
| 关键词 ID/名称判定 | 🔧 `is_id_search(kw)` | `trim()` 后**恰好7位数字**→ID搜索(name空/id=kw)；否则名称搜索(id空/name=kw) |
| 搜索请求体 | 🔧 `search_payload(kw, cred)` | action=list, pageNo=1, pageSize=9999(配置默认)，type/is_valid/valid_type/ctime/chooseDay 全空 |
| 券状态判定 | 🔧 `coupon_status(coupon)` | `couponStatus!=='1'`→已作废(🔴)；`endTime`可解析且 `now>endTime`→已过期(🕚)；否则有效(💡或🌎️共享) |
| 列表排序 | 🔧 `sort_coupons(list)` | 状态升序(有效0/过期1/作废2/未知9)，同状态 ctime 降序 |
| 二维码图标显示 | 🔧 `coupon_status().valid` | valid=true 才显示二维码图标；点击时二次校验，失效提示「当前优惠券已失效…」 |
| 搜索防重入 | 🧠 | `state.isSearching` 为 true 时忽略新搜索；按钮变「搜索中」并禁用 |
| 响应二次过滤 | — | **无**：搜索结果不做状态/有效期隐藏，全部渲染后排序 |

## 2. 作废药店列表
| 过滤 | 类型 | 规则 |
|---|---|---|
| 关键词搜索 | 🔧 `filter_stores(stores, keyword)` | trim+小写后**子串包含**匹配9字段：storeId/storeName/storeCode/providerCode/ctimeStr(createTime)/usertimeStr(useTime)/orderSn/couponPay/statusDesc；任一命中即保留 |
| 创建时间区间 | 🔧 `filter_stores(..., start, end)` | start补`T00:00:00`、end补`T23:59:59`；`ctimeStr\|\|createTime` 空格→T 解析；**闭区间** `>=start 且 <=end`；无创建时间者被剔除 |
| 起止校正 | 🔧 `normalize_create_range()` | 起 > 止 → 止=起（YYYY-MM-DD 字典序） |
| 可勾选药店 | 🔧 `selectable_store_ids(stores, mode)` | 按优惠券模式=全禁用；按药店ID模式=仅 `canCancel=true` 可勾选；全选只操作可作废项 |
| status=99 | 🌐 | 仅作 getStoreList 请求参数，前端未定义语义；不按status隐藏药店 |
| 分页/排序 | — | 无分页、无排序，一次性渲染全部 |

## 3. 赠送
| 过滤 | 类型 | 规则 |
|---|---|---|
| 目标文本非空 | 🧠 | `inputText.trim()` 空 → 提示「请输入赠送目标！」中止（前端唯一校验） |
| parseMode 解析 | 🌐 | auto/storeId/storeCode/mobile 的正则、分隔符、去重、空行过滤**全在后端 giveAll**，前端仅透传 inputText+parseMode |
| 结果展示 | 🧠 | success[] 直接 `join('、')` 无去重排序；failed 按对象 key=原因分组逐条提示；空则「赠送完成，但未返回详细结果」 |
| 自助任务收集 | 🔧 `zizhu.js`规则 | 仅 `status==='pending'`，按 created_at **升序**（最早优先）；抢占条件 `updateWhere(..., 'tasks.<id>.status', 'pending')` 成功才处理 |
| 旧任务清理 | 🧠 | 保留最多10条，按 updated_at/created_at 升序删最旧，仅删 done/failed，pending/processing 永不删 |

## 4. 活动
| 过滤 | 类型 | 规则 |
|---|---|---|
| 活动列表 | 🧠 | API 返回全部显示，无状态/有效期过滤；删除后本地剔除该 id |
| 领券对象解析 | 🔧 `parse_store_subtypes(raw)` | `"0163"`→[0,1,6,3]；`"-1"`→[-1]；含-1则整体[-1]；非整数/< -1/重复 丢弃 |
| 区域树选中 | 🔧 `area_ids_from_tree(nodes, fallback)` | state为数组：`status∈{selected,undetermined}` 且 `assured===true`；为标准对象：selected/checked/undetermined 为真；全未选中才用 fallback |
| 高折扣判定 | 🔧 `is_high_discount(coupon)` | minPay>0且<2000 → 高折扣；满减券(type11)：`(minPay-price)/minPay < 0.98` → 高折扣；打折券(type13)：折算比率<0.98 → 高折扣；免邮券(type25)不判高折扣 |
| 共享策略校验 | 🧠 | 启用+公共共享时才校验：免邮券→「免邮券暂不支持共享！」；高折扣无区域→「优惠较大，请设置至少1个区域！」；高折扣无领券对象→「优惠力度过大，请设置领券对象！」 |
| 抢券时间范围 | 🔧 `grab_range(coupon)` | 今天 ~ 今天+2，且不超过券 endTime 日期（字符串比较），券已过期则仅今天 |
| 二维码活动过滤 | 🧠 | 无活动/过期/禁用时弹确认（建/刷新/启用），仅启用状态活动生成二维码；URL=`dian.ysbang.cn/#/grabCoupon?id={activityId}` |
| 自动刷新过滤 | 🧠 | 仅 `time_refresh_behavior==='auto'` 的活动，每30分钟刷新时间为今天~今天+2（≤券结束日） |
| 共享券过期清理 | 🔧 `is_share_time_expired(text)` | `YYYY-MM-DD`→当天23:59:59；到期即删，无宽限期；coupon_expire_at 或 grab_time.end 过期→清理共享节点 |
| 供应商过滤 | 🧠 | `watchWhere/getWhere('coupons','provider_id','==',providerId)`；docId=`{providerId}::{couponId}`（`.#$[]/`→`_`） |

## 5. 创建券
| 过滤 | 类型 | 规则 |
|---|---|---|
| 折扣解析 | 🧠 | 打折券 `parseDiscount`：98/9.8/0.98 均→9.8折（>10除10，<=1乘10） |
| 有效期模式 | 🧠 | 时间段(selectDateType=0)：起止日期补 00:00:00/23:59:59；天数(=1)：validDays 空→1；validType 仅免邮券提交 |
| 校验顺序 | 🧠 | 名称→minPay→折扣/金额→日期→天数，返回首个错误（见主文档 §5.3） |
| 说明自动生成 | 🧠 | note 空按券类型生成；用户手动改过 note 不再覆盖 |

## 6. Agent 使用原则
1. **先查工具**：🔧 项直接调用 `coupon_filters.py`，不自己写判定逻辑
2. **🧠 项按规则表执行**：严格按 if-else，不凭感觉
3. **🌐 项如实告知**：前端无规则，不要编造（如 parseMode 具体解析、status=99 含义）
4. **不确定性**：规则表未覆盖的 → 标注"前端无此过滤"并询问用户，不臆测
