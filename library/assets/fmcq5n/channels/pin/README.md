# pin · 钉 IP

## 一、方式定义
**不改源，只绕 DNS/线路**：先取一批可达 IP，再在单次调用内启动本地 CONNECT 代理（127.0.0.1 随机端口）把 GitHub 域钉到候选 IP。实现：`channel_pin.py`（内置 IP 池现于治理层 `lines.py`，归位本目录属既定计划）。

## 二、适合的情况
解析被污染、连接被劣化（direct 失败的解药）；git 与 HTTP 通用。浏览器场景用不到它（Agent 侧专用）。

## 三、内部降级链（细粒度）
1. **候选 IP 来源**（动态优先）：本地探测（`sources/ipscan.py`，本机 DNS+TCP 测活）→ DoH（阿里/DNSPod，绕本地 DNS 污染）→ 内置池（本目录 `pools.json`，8 域实测清单）；
2. **候选排序与 failover**：历史好 IP 置顶（`ip_good` 30 分钟 TTL）→ 实测有响应者置前（`ip_alive` 5 分钟 TTL）→ 每域最多 4 候选 × 多轮轮换（`_rotations`，**传输级**换 IP——TCP 连得上但 TLS 被掐的 IP 会白等，必须按"能否传完"换）。

## 四、前提与副作用 / 红线
零系统改动、进程结束即失效；首次本地探测有前置耗时（实测定值：median ≈4.8s / 封顶 8s，到点用已得结果）。代理内单 IP 连接超时收紧（4s，实测 12s 会吃掉预算）。

## 五、实测记录
2026-09-11 真机：6 域 IP 候选逐条拨测定池；TLS 半途失败历史（转发前必须清两端超时，见 `PinProxy._handle` 注释）。
