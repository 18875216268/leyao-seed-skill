# 高级汇报页面生成器 (Executive Report Skill)

生成零依赖、内容驱动、防阅读疲劳的高级感 HTML 汇报网页。
单个 `.html` 文件，内联 CSS，无 JS 框架依赖，直接浏览器打开即用。

---

## 核心原则

1. **内容驱动** — 页面的结构、模块数量、展示形式完全由用户提供的内容决定。不预设固定的模块顺序或数量。
2. **灵活适配** — 根据内容的性质选择最合适的组件（表格、列表、步骤块、引用卡片等），而不是将内容硬塞进固定模板。
3. **左侧导航** — 页面左侧固定浅色导航栏，自动根据内容模块生成锚点目录，当前模块用深色背景高亮，方便长页面跳转。
4. **防阅读疲劳** — 通过卡片、留白、组件交替打断视觉惯性，保持阅读舒适度。
5. **高级商务感** — 深蓝 + 米灰白，衬线标题 + 无衬线正文，克制用色。
6. **零依赖** — 单 HTML 文件，仅引用 Google Fonts + 极少量原生 JS（导航锚点滚动）。

## 布局架构

### 整体布局

```
┌──────────────┬──────────────────────────────────────────┐
│              │                                          │
│   左侧导航    │              主内容区                      │
│   (固定定位)  │         (垂直滚动阅读)                     │
│   ~220px     │         max-width: 880px                 │
│              │                                          │
│  · 报告标识   │   header（标题区）                         │
│  · 目录链接   │   ├── 标题 / 副标题 / 元信息               │
│  · 当前高亮   │                                          │
│              │   内容模块 × N（由内容决定）                 │
│              │   ├── section-header + 内容组件             │
│              │   └── ...                                │
│              │                                          │
└──────────────┴──────────────────────────────────────────┘
```

### 左侧导航栏 `.sidebar-nav`

- 固定在页面左侧，高度 100vh，宽度 220px
- **浅色背景**（与页面主背景协调，使用 `#F0F2F5` 极浅灰）
- 右侧有 `1px` 浅灰分割线与主内容区分隔
- 顶部：报告标识（深蓝衬线字体标题 + 浅灰小字副标题，如"Q4 STRATEGIC REVIEW"）
- 中部：根据页面实际内容模块自动生成的目录锚点链接
- **当前所在模块**：深蓝背景色块（`--primary-blue`）+ 白色文字 + 圆角，视觉突出
- **非活跃项**：深灰文字（`--text-gray`），hover 时加深
- 每个导航项前带小图标（使用 Unicode 符号区分不同模块类型）
- 使用极少量原生 JS 实现滚动监听 + 当前项高亮

### 主内容区 `.main-content`

- 左边距留出导航栏宽度（`margin-left: 220px`）
- 内容区 `max-width: 880px`，居中对齐
- 上下 padding 充足（`50px 40px`）

## 设计系统规范

### 色彩体系（CSS 变量）

```css
:root {
    --primary-blue: #0A3074;
    --sidebar-bg: #F0F2F5;
    --sidebar-border: #E5E7EB;
    --sidebar-text: #4B5563;
    --sidebar-text-active: #FFFFFF;
    --sidebar-active-bg: #0A3074;
    --bg-offwhite: #F8F9FA;
    --card-bg: #FFFFFF;
    --highlight-light: #F4F7FA;
    --text-dark: #1F2937;
    --text-gray: #4B5563;
    --border-light: #E5E7EB;
}
```

**用色规则：**
- 全文只用 `--primary-blue` 一个强调色，绝不引入第二种彩色
- 背景只在 `#F8F9FA`（页面）和 `#FFFFFF`（卡片）之间切换
- 需要额外层次时，用 `--highlight-light` 浅蓝灰色块
- 状态标签（风险等级等）可按需使用语义色：红 `#FEE2E2/#DC2626`、黄 `#FEF3C7/#D97706`、蓝 `#E0E7FF/#4F46E5`、灰 `#F3F4F6/#374151`

### 字体系统

```css
--font-sans: 'Noto Sans SC', sans-serif;
--font-serif: 'Noto Serif SC', serif;
```

- Google Fonts 引入：`Noto Sans SC:wght@400;500;700` + `Noto Serif SC:wght@500;700;900`
- h1 用衬线体，h2/h3/正文全部无衬线
- 基础字号 `15px`，行高 `1.7`

### 标题层级

| 层级 | 字体 | 字号 | 颜色 | 用途 |
|------|------|------|------|------|
| h1 | Serif | 2.4rem | `--primary-blue` | 页面主标题，仅出现一次 |
| h2 | Sans | 1.4rem / 700 | `--text-dark` | 模块标题，配编号标签和蓝色底线 |
| h3 | Sans | 1.15rem / 700 | `--primary-blue` | 卡片内小标题，左侧带蓝色竖条 |

### 背景纹理

```css
.main-content {
    background-color: var(--bg-offwhite);
    background-image: radial-gradient(#d1d5db 1px, transparent 1px);
    background-size: 24px 24px;
}
```

## 组件库

以下组件是可用的构建块。**根据内容需要灵活选用，没有固定的使用顺序或数量要求。**

### 1. 模块标题栏 `.section-header`

每个内容模块的入口。包含编号标签 + h2 标题 + 底部蓝色粗线。编号标签为小字体深蓝背景白色文字的标签样式（类似 `SECTION 01 // 模块类型`）。

```html
<div class="section-header" id="section-N">
    <span class="section-label">SECTION 01 // 类型标签</span>
    <h2>模块标题</h2>
</div>
```

- 编号标签文字可灵活使用中英文，如 `SECTION 01 // STRATEGIC OUTLOOK`、`第一部分 // 核心结论`
- 标签内容应与该模块的性质匹配，不必千篇一律

### 2. 白色卡片 `.card`

所有内容的基础容器。纯白背景、圆角 8px、浅边框、极轻投影。

```html
<div class="card">
    <!-- 内容 -->
</div>
```

**强调变体** `.card-light`：浅蓝灰背景 + 左侧 4px 蓝色竖线，用于需要视觉突出的内容（摘要、关键结论、里程碑等）。

```html
<div class="card card-light">
    <!-- 强调内容 -->
</div>
```

### 3. 垂直无序列表 `.v-list`

替代原生 `<ul>`，统一圆点样式为蓝色小圆点。

```html
<ul class="v-list">
    <li>列表项内容</li>
</ul>
```

### 4. 垂直步骤块 `.step-block`

用于展示有逻辑递进关系的内容（流程步骤、阶段分解等）。左侧时间线 + 圆形节点。

```html
<div class="step-block">
    <div class="step-title">步骤标题</div>
    <ul class="v-list">
        <li>步骤内容</li>
    </ul>
</div>
```

### 5. 高级商务表格 `.data-table`

用于展示结构化数据。

```html
<div class="table-wrapper">
    <table class="data-table">
        <thead>
            <tr><th>列标题</th><th>列标题</th></tr>
        </thead>
        <tbody>
            <tr><td>内容</td><td>内容</td></tr>
        </tbody>
    </table>
</div>
```

- 表格内可嵌套 `.v-list` 实现单元格内的多点列举
- 用 `style="width: X%"` 控制列宽比例

### 6. 内联高亮组件

- **关键词高亮** `.focus`：蓝色粗体，`<span class="focus">关键词</span>`
- **标签徽章** `.badge`：浅蓝底 + 蓝色字小标签，`<span class="badge">标签</span>`
- **语义色标签**（仅在需要状态区分的场景使用）

### 7. 大段正文 `.prose`

当内容确实是连贯叙述性文字（如分析报告的论述段落），不适合强行拆解为列表时，使用 `.prose` 容器。允许多个段落连续出现，但通过增大段间距和舒适行高保持可读性。

```html
<div class="prose">
    <p>叙述性段落文字...</p>
    <p>下一段落...</p>
</div>
```

## 生成工作流（核心）

### 第一步：深度理解内容

收到用户提供的内容后，先完整阅读并理解：
- 这份材料的**性质**是什么？（工作汇报？数据分析？方案提案？培训大纲？项目复盘？战略规划？）
- 内容的**内在逻辑**是什么？（时间线？因果关系？并列分类？总分结构？问题-分析-方案？）
- 有哪些**天然的分块**？（尊重原始内容的结构划分，不强行重组）
- 哪些内容适合**视觉突出**？（核心结论、关键数据、重要决策）
- 有哪些需要**结构化展示**的数据？（对比、进度、清单、指标）

### 第二步：设计页面结构

根据第一步的理解，为这份具体内容设计专属的页面结构：

- **模块划分**：根据内容的天然分块决定有几个 section，每个 section 叫什么名字
- **导航目录**：左侧导航的目录项直接对应模块划分
- **标题区设计**：根据内容性质决定标题区放什么信息（不一定需要副标题、不一定需要元信息卡片）
- **组件选择**：为每个模块的内容选择最合适的展示组件

### 第三步：组件匹配参考

以下是常见内容类型与推荐组件的对应关系，仅供参考，不是强制规则：

| 内容类型 | 推荐组件 | 说明 |
|----------|----------|------|
| 核心结论 / 摘要 | `.card-light` | 视觉突出 |
| 并列要点 | `.v-list` | 简洁清晰 |
| 有序流程 / 阶段 | `.step-block` | 体现递进关系 |
| 多维结构化数据 | `.data-table` | 行列对比一目了然 |
| 连贯论述分析 | `.prose` | 保持阅读流畅 |
| 关键数据/指标 | `.focus` + `.badge` | 内联高亮 |
| 补充说明 / 备注 | `.card-light` 或普通 `.card` 内灰字 | 降低视觉权重 |

### 第四步：生成 HTML

1. 按照布局架构搭建页面骨架（左侧导航 + 主内容区）
2. 左侧导航根据实际模块生成目录
3. 按第二步设计的结构组装内容
4. 确保所有 CSS 内联（`<style>` 标签内）
5. 添加导航滚动监听 JS（`<script>` 标签内，原生 JS）

### 第五步：质量检查

- 内容是否完整忠实地呈现了用户提供的材料？（不遗漏、不编造）
- 组件选择是否合理？（不是所有内容都要拆成列表，叙述性文字可以保留段落形式）
- 导航目录是否与页面模块对应？
- 视觉节奏是否舒适？（组件类型交替，避免连续大段同类组件）
- 留白和间距是否充足？

## 微排版指南

1. **组件交替** — 避免连续使用同类组件（如连续 5 个 v-list），用不同组件类型制造视觉节奏
2. **表格优先** — 凡涉及多维信息（时间×事项、类别×描述×结果），优先考虑 `.data-table`
3. **允许段落** — 分析论述类内容可以使用 `.prose` 段落，不必强行拆为列表
4. **重点标记** — 关键词用 `.focus`，分类用 `.badge`，但不要过度使用
5. **留白即呼吸** — 卡片 padding `30px`，列表项间距 `12px`，步骤块间距 `24px`
6. **表格嵌套列表** — `<td>` 内可放 `.v-list` 处理多条目单元格

## 自定义与变体

### 换色方案

修改 `:root` 中的 `--primary-blue` 和 `--sidebar-active-bg` 可全局换色（侧边栏浅色背景通常不需要改）：

| 场景 | 主色 / 激活背景色 | 侧栏背景 |
|------|-------------------|----------|
| 默认商务 | `#0A3074` | `#F0F2F5`（浅灰） |
| 科技/创新 | `#1E40AF` | `#F0F2F5` |
| 金融/稳重 | `#1F2937` | `#F0F2F5` |
| 教育/温和 | `#065F46` | `#F0F4F0` |
| 品牌定制 | 替换为品牌主色 | 保持浅色或微调 |

### 内容密度

- 标准版（默认）：卡片 `padding: 30px`，适合大屏阅读
- 紧凑版：卡片 `padding: 20px`，适合内容密集的报告
- 宽松版：卡片 `padding: 40px`，适合领导级简报

## 注意事项

- 这是**长页面滚动阅读**模式，配合左侧导航快速跳转
- 导航栏使用少量原生 JS 实现滚动监听和当前项高亮
- 打印时左侧导航栏自动隐藏（`@media print` 规则）
- 如需 PDF，浏览器直接 `Ctrl+P` 打印为 PDF 即可
- **最重要的原则：忠实呈现用户内容，不添加用户未提供的内容，不预设固定结构**
